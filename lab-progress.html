Before you start

Run commands from the repository root. You need Podman, Podman Compose, Bash, Git, OpenSSH, curl, and jq. Keep ports 8929, 2222, 5000, 8083, and 8084 free. The default-branch pipeline deploys stage to localhost:8083; production is a manual job at localhost:8084.

Open GitLab sign-in ↗Read source guide




Clear the current GitLab instance
Start from a completely fresh local lab.
podman stop -a && podman rm -a && \
podman rmi -f otus-gitlab-runner:local
podman ps -a
rm -rf ./local/gitlab ./local/runner ./local/registry ./local/gitlab-root-password.env ./projects/cocktail-search/.git
Warning: this removes local GitLab, Runner, and Registry data, the local password file, the sample project's Git history, and can stop unrelated Podman containers.


Initialize local credentials
Creates the ignored administrator-password file. It never prints the password itself.
./scripts/initialize-gitlab.sh
Verify: local/gitlab-root-password.env exists. Never commit or share it.


Start GitLab CE
Launch GitLab in the background. First startup often takes 5–10 minutes.
podman compose up -d gitlab
Verify: podman compose ps shows GitLab running.


Wait for readiness and sign in
A running container is not necessarily a ready GitLab. Poll its sign-in endpoint first.
until curl --fail --silent --show-error http://localhost:8929/users/sign_in >/dev/null; do
  echo "not yet"; sleep 30
done
echo "GitLab is ready"
Verify: sign in as root; get the password locally with grep '^GITLAB_ROOT_PASSWORD=' local/gitlab-root-password.env.


Start local OCI Registry
Start the local-only image hand-off point before building and registering the Runner.
podman compose up -d registry
curl --fail --silent --show-error http://127.0.0.1:5000/v2/_catalog
Verify: the catalog responds. The Registry is HTTP-only and local; see the Registry step for the Docker push and Podman pull exercise.


Build and start the Runner
The Runner owns its own internal Docker Engine; it does not use the host socket.
podman compose build runner
podman compose up -d runner
podman compose exec runner docker info
podman compose exec runner gitlab-runner --version
Verify: both checks return successfully; docker info describes the Runner’s internal daemon.


Register the group Runner
Create or reuse the local gulash-prj group and register a Docker-executor Runner.
./scripts/register-group-runner.sh
podman compose exec runner gitlab-runner verify
Verify: it reports a valid Runner and it appears in the group Runner page.


Verify Registry image transfer
Automatically push from nested Docker, inspect it there, then pull the same image with Podman.
podman compose exec -T runner docker push registry.localhost:5000/learning/registry-check:dashboard
podman compose exec -T runner docker image inspect registry.localhost:5000/learning/registry-check:dashboard
podman pull --tls-verify=false registry.localhost:5000/learning/registry-check:dashboard
Verify: the action succeeds and the Podman pull uses the same image reference.


Configure SSH trust and identity
Safely record the server host key, then add your public key to GitLab.
./scripts/trust-local-gitlab-host-key.sh
./scripts/add-user-ssh-key.sh
ssh -o StrictHostKeyChecking=yes -p 2222 -T git@localhost
Verify: SSH returns a GitLab greeting. The scripts use your public key, never your private key.


Publish and deploy the application
Create gulash-prj/cocktail-search, publish the root-tracked application files, then verify automatic stage and manual production deployment.
./scripts/create-cocktail-search-project.sh
cd projects/cocktail-search
git init --initial-branch=main
git add .
git commit -m "Publish application to local GitLab"
git remote add origin ssh://git@localhost:2222/gulash-prj/cocktail-search.git
git push -u origin main
Verify: main runs test, build_check, and automatically deploys stage at http://localhost:8083/actuator/health.
Manual action required: deploy PROD. Open the pipeline, press Play for deploy_prod, then verify http://localhost:8084/actuator/health.
